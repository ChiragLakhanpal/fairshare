# The /present deck: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correct the data claims and the pace definition, then build a 36-minute deck with an 11-minute short path at `/present` in the fairshare app: a notes window, live demo jumps, animated diagrams, and every number filled in from a query.

**Architecture:** Phase 1 fixes labels, parity wording and pace in the lakehouse, Genie, the app and the figures, and ships on its own. Phase 2 deploys a two-slide deck to prove that a framed diagram steps correctly on the Databricks App. Phases 3 and 4 add the facts file, the new figures, the animated versions, every slide, the notes window and the demo jumps. Phase 5 writes the speaker notes and gets rehearsal ready.

**Tech Stack:** DuckDB and Databricks SQL; Python figure builders on the diagram-design plugin; React 19, Vite 7, TypeScript, Tailwind v4, motion; Vitest, Playwright, pytest; bun.

**Spec:** `docs/superpowers/specs/2026-10-19-present-design.md`. Paths below are relative to the fairshare repo root.

## Global Constraints

- Copy everywhere (slides, notes, figures, docs, app strings) is plain words a 10th grader follows, with no em or en dashes. Buttons are short verb phrases (CLAUDE.md rule 9). Every slide text and note gets a humanizer pass.
- Numbers on slides and in notes come only from `web/src/deck/facts.json`, written as `{snake_case}` placeholders. Digits allowed outside a placeholder: the years 2025 and 2026, quarters (Q1 to Q4), "figure NN", and the names gpt-5-mini, Qwen3-Next, T-100, Dynamics 365, Microsoft 365 and "6 am".
- The seat data is made up. Its label: "made-up seat shares, one per route; the T-100 loader (`data/t100.py`) has never run". Every data figure says "synthetic data" in its logo band through `aa.brand(tag="fairshare · synthetic data")`. Nobody says a made-up seat share as if it were AA's.
- The parity twin is a SQL copy of the Power BI measure, not Power BI. It covers six of the seven numbers (pace has none).
- No interviewer names in the repo, on screen or in notes. Notes name roles ("the sales director"). The names live only in `.env` as `FAIRSHARE_DECK_BLOCKLIST` (comma separated), and are never printed.
- SQL stays portable and never destructive (CLAUDE.md rules 4 and 5). A definition changes in all of its places together, and the commit title says a definition changed (rule 2).
- Local Python runs as `FAIRSHARE_BACKEND=duckdb .venv/bin/python ...`, because the laptop's `.env` points at Databricks. Stop any running app before `lakehouse/run.py`, which rewrites the DuckDB file.
- The web side uses bun, because this machine has no npm. From `web/`: `bun run test`, `bun run build`, and `bunx playwright test` with `bunx vite --port 5173` running.
- Figures use diagram-design with the american-airlines profile (`.diagram-design` at the root): a 1280 by 720 viewBox, the plugin's verifiers, `docs/diagrams/src/lint.py`, then a PNG (`NODE_PATH=web/node_modules node docs/diagrams/src/export_png.cjs <html> <png>`, 2560 by 1440) and an SVG (the plugin's `export_svg.py`). `$DD` below means `~/.claude/plugins/cache/diagram-design/diagram-design/2.6.110`.
- Motion pages keep the plugin's controller byte for byte and hold exactly one script, with no inline event handlers: `verify-motion.py` and `lint-skin.py` fail on either. Budget per figure: at most 8 steps, 12 marked items, 2 at once.
- Main path 35 to 40 minutes; short path about 11. Checkpoints: precall done by 29 and start by 36 (full), ask done by 5 and start by 11 (short).
- Chirag commits only when he asks. Each task ends with a commit step: before executing, ask him once whether the per-task commits are approved. If not, stage the files and skip the commit.
- Secrets stay in `.env` and are never printed.

## Changes from the spec

Each was checked against the code and the data while planning or in the two reviews.

1. Embed mode puts no script in the diagram page. `verify-motion.py` allows one script per motion document (line 371) and `lint-skin.py` rejects `on*` attributes (line 165), so the spec's pre-controller script and its non-blocking font load cannot pass. Instead the page carries embed CSS keyed on `html[data-embed]`. The deck waits for the controller (`[data-motion-root].motion-ready`), sets `data-embed`, and sends Home or End, which pauses the reveal before its first step (the engineer ran this against the committed 01 page: ready at 52 ms, still on step 0 two seconds after Home). - [ ] **Step 3: Implement the types and the pure functions in `web/src/lib/deck.ts`**

`move` on a slide that is on the path steps along it and stops at the ends. On a backup slide it steps among the backup slides. On a main slide that is not on the short path, it picks the nearest path slide in that direction by position in `slides`. `arrivalKey` returns End when going back, after two seconds (so a late start never plays on its own), or under reduced motion (the controller's keys ignore reduced motion). `sendKey` dispatches `new (f.contentWindow as typeof window).KeyboardEvent("keydown", { key, bubbles: false, cancelable: true })` on the frame's `[data-motion-root]`, because the controller listens there, not on the document. `frameState` returns null unless the frame has `data-ready="1"` (set by `SlideView`), and otherwise the root's `data-step-current` and `data-step-count` as numbers. Both read the frame's document inside try and catch, because an aborted or blocked frame cannot be read.
